# v12 Local Sales Read API

## Overview

This v12 milestone adds read-only API access to local sale records created by the explicit local sale-completion workflow.

Source table:

```text
listing_draft_sales
```

Create path, from the previous v12 milestone:

```text
POST /api/v1/listings/drafts/{draft_id}/complete-sale
```

Read paths, added by this milestone:

```text
GET /api/v1/sales/{sale_id}
GET /api/v1/sales
```

This is local SaveRoom workflow state only. It is not marketplace integration, order import, fulfilment, shipping, payment capture, live provider pricing, or LLM automation.

## Endpoints

### Get one local sale

```text
GET /api/v1/sales/{sale_id}
```

Behaviour:

- loads a local sale by `sale_id`;
- returns `404 local_sale_not_found` when missing;
- returns local sale fields only;
- does not mutate sales, reservations, or inventory;
- does not call providers, marketplaces, network APIs, or LLM APIs.

Example response:

```json
{
  "data": {
    "sale_id": "sale_...",
    "draft_id": "ld_...",
    "reservation_id": "ldr_...",
    "inventory_item_id": "...",
    "card_key": "en:sv03-223",
    "quantity": 1,
    "platform": "whatnot",
    "sale_price": 12.5,
    "currency": "GBP",
    "status": "completed",
    "sold_at": "2026-07-02T10:00:00Z",
    "buyer_reference": "plain local buyer reference",
    "external_order_reference": "plain local order reference",
    "notes": "confirmed local sale",
    "created_at": "...",
    "updated_at": "..."
  },
  "metadata": {
    "api_version": "v1",
    "contract": "v12-local-sales-read",
    "generated_at": "..."
  }
}
```

### List local sales

```text
GET /api/v1/sales
```

Default behaviour:

- lists local sales with `status=completed` by default;
- orders by `sold_at DESC, created_at DESC, sale_id DESC`;
- returns project-standard pagination;
- does not mutate local sale rows, reservations, or inventory;
- does not call providers, marketplaces, network APIs, or LLM APIs.

Example response:

```json
{
  "data": [],
  "pagination": {
    "limit": 50,
    "offset": 0,
    "count": 0,
    "total": 0,
    "has_more": false
  },
  "metadata": {
    "api_version": "v1",
    "contract": "v12-local-sales-read",
    "generated_at": "..."
  }
}
```

## Filters

`GET /api/v1/sales` supports:

```text
draft_id
inventory_item_id
card_key
platform
status
date_from
date_to
limit
offset
```

Filter rules:

- `draft_id` exact-matches `listing_draft_sales.draft_id`.
- `inventory_item_id` exact-matches `listing_draft_sales.inventory_item_id`.
- `card_key` exact-matches `listing_draft_sales.card_key`.
- `platform` exact-matches `listing_draft_sales.platform`.
- `status` exact-matches `listing_draft_sales.status` and defaults to `completed`.
- `date_from` filters `sold_at >= date_from`.
- `date_to` filters `sold_at <= date_to`.
- Date filters intentionally use `sold_at`, not `created_at`, because users are looking for sale timing rather than record creation timing.

Example queries:

```text
GET /api/v1/sales?draft_id=ld_...
GET /api/v1/sales?inventory_item_id=...
GET /api/v1/sales?card_key=en:sv03-223
GET /api/v1/sales?platform=whatnot
GET /api/v1/sales?status=completed
GET /api/v1/sales?date_from=2026-07-01T00:00:00Z&date_to=2026-07-31T23:59:59Z
GET /api/v1/sales?limit=50&offset=0
```

## Safety boundaries

The read endpoints do not:

- call `_get_justtcg_price_data()`;
- call JustTCG, TotalTCG, TCGplayer, Cardmarket, eBay, Whatnot, Shopify, or LLM APIs;
- call live provider APIs;
- call marketplace APIs;
- publish listings;
- create marketplace listings;
- import marketplace orders;
- capture payments;
- perform fulfilment or shipping;
- mark inventory sold;
- decrement stock;
- create local sale records;
- update local sale records;
- update reservations;
- update physical inventory state;
- ask for or need API keys;
- return API keys, request headers, account metadata, raw provider payloads, private provider paths, sanitized candidates, raw filesystem paths, marketplace credentials, marketplace account IDs, or generated marketplace listing IDs.

`external_order_reference` is allowed only as manually supplied plain local text metadata. It is not generated by these endpoints and is not interpreted as proof of a marketplace order.

## Known limitations

- This is not a full sales/order system.
- It does not provide analytics, totals, charts, profit calculations, sales reconciliation, refunds, fulfilment, postage, or customer management.
- It does not publish, revise, or end marketplace listings.
- It does not import marketplace orders.
- It does not validate external order references against marketplaces.
- It only reads local sale rows created by explicit local sale completion or equivalent local database fixtures.
